# Security And Sensitive Feedback

## Documentation-Only Scope

This repository contains a proposed governance and security architecture for review. It contains no production software and makes no security or compliance claim.

## Sensitive Reports

Do not place secrets, credentials, personal data, private customer material, real incident details, or unpublished vulnerability information in a public issue or pull request.

GitHub private vulnerability reporting is the designated repository channel for sensitive security feedback and must be enabled before public release. Until that channel is available, do not publish sensitive details. Use a private contact method listed on the repository owner's GitHub profile, or open a public issue containing only a request for a private reporting route.

## Review Reports

Non-sensitive documentation concerns may be reported through the review-feedback issue form. Useful reports include:

- unsafe or ambiguous governance language,
- missing authority or accountability boundaries,
- missing egress or stop-state handling,
- overclaim risks,
- privacy or legal-review concerns,
- inconsistencies between registries, matrices, policies, and test cases.

## Response Boundary

A received report is review input only. It does not authorize scanning, exploitation, remediation, live incident response, provider-restricted capability, or autonomous action against any system.
