# Repository Governance

## Scope

This file governs the canonical Governance-First Security Architecture Project repository.

It is repository governance only. It does not authorize implementation, runtime behavior, automation, live integration, real-data use, security claims, compliance claims, or production use.

## Canonical Repository

The canonical project source is:

```text
https://github.com/CarlMartinDahl/governance-first-security-architecture
```

Martin Dahl is the project originator and canonical maintainer.

Only material accepted into the canonical repository by the canonical maintainer is part of an official project revision. A fork, copy, adaptation, workshop output, or independent implementation is not an official release unless the canonical repository explicitly records it as one.

## Current Decision Authority

During the documentation freeze, the canonical maintainer decides whether a proposed repository change is:

- accepted review feedback,
- a bounded clarification or correction,
- a scope reduction,
- a claim weakening,
- repository-governance maintenance,
- deferred for additional review,
- rejected as model expansion or implementation work.

Accepted material feedback must be recorded in the Post-Review Revision Log when required by the contribution process.

## Contributions

Contributors retain copyright in their original contributions and agree to distribute accepted documentation contributions under CC BY-SA 4.0, as described in [CONTRIBUTING.md](CONTRIBUTING.md).

Contribution does not by itself grant release authority, project-name control, security or compliance authority, or authority to represent an independent fork as official.

## Forks And Derivatives

Forks and derivatives are welcome when they comply with the applicable license and attribution requirements.

They should:

- identify the canonical source,
- credit Martin Dahl and other applicable contributors,
- describe material changes,
- use a distinguishable project or distribution name,
- state that they are independent unless formally accepted into the canonical repository,
- avoid suggesting endorsement, validation, certification, or official status.

See [ATTRIBUTION.md](ATTRIBUTION.md) and [PROJECT-IDENTITY.md](PROJECT-IDENTITY.md).

## Future Code Boundary

This repository contains no implementation code and currently accepts none.

If software work is later authorized through an explicit review-gate decision, the intended default license for original project code is Mozilla Public License 2.0. No MPL-2.0 license grant exists until code and the corresponding license notice are actually added to the repository.

Any future code-license activation must be recorded as a separate governance decision and must not be inferred from the current documentation license.
